# Gains — SwiftUI iOS + watchOS Workout Tracker

## Context

Greenfield project. Building a polished, Apple-quality workout tracking app called **Gains**. Positioning: *"The first workout app that coaches you forward, not just records the past."* Primary inspiration: Bevel's clean, frictionless logging UX. Key differentiators over Strong / Hevy / Fitbod: animated muscle recovery map, strength fingerprint radar, AI progressive overload coach, milestone predictions, and shareable "Gains Wrapped" cards.

## Xcode Project Setup

### Step 1 — Create the iOS app project

1. Open Xcode → **File → New → Project**
2. Choose **iOS → App** template → Next
3. Fill in:
   - **Product Name**: `Gains`
   - **Team**: your Apple Developer account
   - **Organization Identifier**: `com.yourname` (bundle ID becomes `com.yourname.gains`)
   - **Interface**: SwiftUI
   - **Language**: Swift
   - **Storage**: SwiftData ✅
   - Uncheck "Include Tests" for now (add later)
4. Save the project **inside** your `gains/` git folder (so the `.xcodeproj` sits at `gains/Gains.xcodeproj`)

### Step 2 — Add the watchOS companion target

1. **File → New → Target**
2. Choose **watchOS → Watch App** → Next
3. Fill in:
   - **Product Name**: `Gains Watch App`
   - **Bundle Identifier**: `com.yourname.gains.watchkitapp`
   - Check **"Mirror iPhone App"** so it shares the same container
4. Xcode will ask "Activate 'Gains Watch App' scheme?" → click **Activate**

### Step 3 — Configure project-level settings

In the **Gains** project navigator root → select the project → **Info** tab:
- Set iOS Deployment Target: **17.0**
- Set watchOS Deployment Target: **10.0**

### Step 4 — Add capabilities to the iOS target

Select the **Gains** target → **Signing & Capabilities** tab → click **+ Capability** for each:
- **HealthKit** — enables read/write of health data
- **Push Notifications** — required for ActivityKit Live Activities
- **Background Modes** → check **"Background fetch"** and **"Remote notifications"**

### Step 5 — Add capabilities to the Watch target

Select the **Gains Watch App** target → **Signing & Capabilities**:

### Key models in detail

**`SetType` enum** (stored on `LoggedSet` and `TemplateSet`):
```swift
enum SetType: String, Codable, CaseIterable {
    case warmup      // "W"  — dim yellow label, excluded from volume/PR calculations
    case working     // "1"  — default, counts toward volume and PRs
    case dropSet     // "D"  — logged at lower weight immediately after a working set
    case failure     // "F"  — red label, working set taken to failure
    case cooldown    // "C"  — dim blue, excluded from volume
    case myorep      // "M"  — cluster/myo-rep set marker

    var label: String   // single-char display label
    var color: Color    // tint used in set row
    var countsTowardVolume: Bool
    var countsTowardPR: Bool    // only .working and .failure
}
```

**`RestTimerConfig.swift`**:
```swift
@Model class RestTimerConfig {
    var defaultSeconds: Int          // global default (e.g. 90)
    var warmupSeconds: Int           // e.g. 45
    var workingSeconds: Int          // e.g. 120
    var dropSetSeconds: Int          // e.g. 15
    var failureSeconds: Int          // e.g. 180
    var autoStartAfterSet: Bool      // start timer automatically on set complete
    var hapticAtHalfway: Bool
    var hapticAtComplete: Bool
    var soundEnabled: Bool
}
// One global RestTimerConfig owned by User.
// Per-exercise override: optional restTimerSeconds on TemplateExercise.
```

**`LoggedSet.swift`**:
```swift
@Model class LoggedSet {
    var setType: SetType
    var weight: Double
    var reps: Int
    var rpe: Double?            // 1–10 Rate of Perceived Exertion, optional
    var completedAt: Date?
    var isCompleted: Bool
    var notes: String?
}
```

**`TemplateSuperset.swift`** — groups 2–4 exercises performed back-to-back with no rest between them, one shared rest timer after the round:
```swift
@Model class TemplateSuperset {
    var exercises: [TemplateExercise]   // ordered, 2–4
    var restSeconds: Int?               // override; nil = use RestTimerConfig.workingSeconds
    var label: String?                  // e.g. "Chest & Back Superset"
}
```

**`LoggedSuperset.swift`** — mirrors TemplateSuperset for live sessions.

**`Exercise.swift`** additions:
```swift
var gifUrl: String                    // from ExerciseDB CDN, loaded via AsyncImage
var plateCalculatorEnabled: Bool      // show plate breakdown for barbell exercises
```

**Key computed properties:**
- `Exercise.estimatedOneRM(weight:reps:)` — Epley: `weight * (1 + reps/30)`
- `Exercise.plateBreakdown(targetWeight:barWeight:availablePlates:)` → `[(Double, Int)]`
- `WorkoutSession.totalVolume` — working + failure sets only
- `WorkoutSession.formattedDuration` — "1h 23m"
- `WorkoutSession.muscleGroupVolume` — `[MuscleGroup: Double]` for recovery map

## Exercise Library (Seed Data)

### Source: ExerciseDB via RapidAPI

Use **ExerciseDB** (`exercisedb.p.rapidapi.com`) — free-tier API, 1,300+ exercises with GIF URLs.

**Step 1 — Get an API key**
1. Sign up at [RapidAPI ExerciseDB](https://rapidapi.com/justin-WFnsXH_t6/api/exercisedb) (free tier: 50 req/day)
2. Copy your `X-RapidAPI-Key`

**Step 2 — Fetch raw JSON**
```bash
curl -s "https://exercisedb.p.rapidapi.com/exercises?limit=1300&offset=0" \
  -H "X-RapidAPI-Key: YOUR_KEY" \
  -H "X-RapidAPI-Host: exercisedb.p.rapidapi.com" \
  | python3 -m json.tool > exercises_raw.json
```

**Step 3 — Transform to app schema** (`Scripts/transform_exercises.py`):
```python
import json

EQUIPMENT_MAP = {
    "barbell": "barbell", "dumbbell": "dumbbell", "cable": "cable",
    "machine": "machine", "body weight": "bodyweight",
    "band": "machine", "kettlebell": "dumbbell",
    "leverage machine": "machine", "rope": "cable",
    "ez barbell": "barbell", "weighted": "bodyweight",
    "assisted": "bodyweight", "sled machine": "machine",
    "smith machine": "barbell", "trap bar": "barbell",
    "upper body ergometer": "cardio", "skierg machine": "cardio",
    "elliptical machine": "cardio", "roller": "bodyweight",
}
CATEGORY_MAP = {
    "chest": "chest", "back": "back", "shoulders": "shoulders",
    "upper arms": "arms", "lower arms": "arms",
    "upper legs": "legs", "lower legs": "legs",
    "waist": "core", "cardio": "cardio", "neck": "other",
}

with open("exercises_raw.json") as f:
    raw = json.load(f)

out = []
for ex in raw:
    out.append({
        "name": ex["name"].title(),
        "category": CATEGORY_MAP.get(ex["bodyPart"], "other"),
        "primaryMuscle": ex["target"],
        "secondaryMuscles": ex.get("secondaryMuscles", []),
        "equipment": EQUIPMENT_MAP.get(ex["equipment"], "other"),
        "instructions": ex.get("instructions", []),
        "gifUrl": ex.get("gifUrl", ""),
        "isCustom": False,
        "plateCalculatorEnabled": ex["equipment"] in ("barbell", "ez barbell", "trap bar"),
    })

with open("../Gains/Resources/exercises.json", "w") as f:
    json.dump(out, f, indent=2)
print(f"Wrote {len(out)} exercises")
```

Run: `python3 Scripts/transform_exercises.py`

**Step 4 — Bundle and seed**

Add `exercises.json` to `Gains/Resources/` in Xcode. In `SeedData.swift`:
```swift
func seedExercisesIfNeeded(context: ModelContext) {
    guard !UserDefaults.standard.bool(forKey: "exercisesSeeded") else { return }
    guard let url = Bundle.main.url(forResource: "exercises", withExtension: "json"),
          let data = try? Data(contentsOf: url),
          let dtos = try? JSONDecoder().decode([ExerciseDTO].self, from: data) else { return }
    for dto in dtos { context.insert(Exercise(from: dto)) }
    try? context.save()
    UserDefaults.standard.set(true, forKey: "exercisesSeeded")
}
```

Call from `GainsApp.swift` `.onAppear` after `ModelContainer` is ready.

**Alternative (free, no key): wger**
`https://wger.de/api/v2/exercise/?format=json&language=2&limit=100` — ~300 exercises, no GIFs, open-source.

## Novel Differentiators

### 1. Animated Muscle Recovery Map
`MuscleBodyMap.swift` — SVG-based anatomical silhouette (front + back toggle). Each muscle group region is a `Path` filled with a color interpolated **green → amber → red** based on training recency and accumulated volume. Updated on every workout save.

- Data: `WorkoutSession.muscleGroupVolume` aggregated over rolling 7 days
- Recovery model: muscle reaches green after `restDaysNeeded` (chest = 2 days, legs = 3, arms = 1.5)
- Tap a muscle region → sheet: last trained (X days ago), volume this week, suggested exercises
- Animates on appear: muscles "light up" in ripple order from most recently trained

### 2. Strength Fingerprint (Radar Chart)
`StrengthFingerprint.swift` — Spider/radar chart across 6 movement pattern axes:
**Push / Pull / Squat / Hinge / Carry / Core**

- Each axis = estimated 1RM for the best exercise in that pattern, normalized to bodyweight
- Faint "population average" shape overlaid for reference
- Shareable as a card image via `ImageRenderer`
- Shown on Profile tab + inside Gains Wrapped

### 3. AI Progressive Overload Coach
`OverloadCoach.swift` — Stateless service; inspects session history and returns `NextSessionPlan`:

```swift
struct NextSessionPlan {
    let exercise: Exercise
    let suggestedSets: Int
    let suggestedReps: Int
    let suggestedWeight: Double
    let rationale: String        // "Hit 185×5×3 last session — adding 2.5kg"
    let progressionScheme: ProgressionScheme
}

enum ProgressionScheme {
    case linear(increment: Double)   // beginner: add weight every session
    case wave(pattern: [Double])     // intermediate: 3-week wave
    case deload                      // after 3 stalled sessions
}
```

- Shown as a coach card on Today tab: "Bench Press today: try 190×5×3 (+2.5kg)"
- Plateau detection: 3+ sessions with no volume/weight increase → suggest deload
- Annotated on 1RM chart: "Plateau detected" badge

### 4. Milestone Prediction Line
Every 1RM chart gets a **dotted projection line** via linear regression on the last 8 sessions, plus a shaded confidence cone that widens over time. Milestone weights annotated (1 plate / 2 plates / bodyweight / 2× bodyweight).

```swift
// ProgressViewModel
func predictedOneRM(for exercise: Exercise, daysAhead: Int) -> (predicted: Double, lower: Double, upper: Double)
```

### 5. Gains Wrapped — Shareable Cards
`WrappedCardView.swift` rendered via `ImageRenderer`. All metrics pulled from Apple Health so data reflects everything the user does, not just what's logged in Gains.

**Monthly Wrapped** (any time; auto-prompted on 1st of new month):
- Workouts completed + current streak
- Total time working out (hours + minutes, from Health)
- Total steps (from Health)
- Total active calories burned (from Health)
- Total distance — walking + running + cycling (from Health)
- Top 3 exercises by volume
- Biggest PR hit that month
- Most consistent training day of the week
- Volume vs. prior month delta (+/- %)
- Strength Fingerprint snapshot

**Annual Wrapped** (Dec 31 / Jan 1):
- Everything above, annualized
- Total tonnage ("You lifted X elephants")
- Best single month
- Strength Fingerprint: this year vs. last year overlaid

**Per-workout card** (shown on workout complete):
- Duration, total volume, PRs, set type breakdown

Cards designed for Instagram Stories (1080×1920). Exported via `ImageRenderer` at 3× scale.

### 6. Volume Landmarks (MEV / MAV / MRV)
Per muscle group, track weekly set count against research-backed thresholds:
- **MEV** (Minimum Effective Volume) — floor for adaptation
- **MAV** (Maximum Adaptive Volume) — sweet spot
- **MRV** (Maximum Recoverable Volume) — ceiling

Displayed as a horizontal zone bar. Gray (below MEV) → green (MEV–MAV) → amber (MAV–MRV) → red (above MRV). Default values based on RP hypertrophy research; user-adjustable in settings.
