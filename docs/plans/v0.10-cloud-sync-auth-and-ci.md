# Implementation Plan: `v0.10` — Cloudflare D1 Delta Sync, Better Auth & CI/CD

> **Agent Prompt**: Implement `v0.10` according to this plan. Prerequisite: `v0.9` is complete. Read `docs/01-architecture-and-tech-stack.md` and `docs/02-database-and-sync-spec.md` for reference.

---

## 1. Goal & Scope

Connect the local-first web application to the **100% Free-Tier Cloudflare Backend** (`Cloudflare Workers` + `Hono` + `Cloudflare D1 SQLite`), integrate **Better Auth** (Passkeys, Email/Password, Personal API Tokens for MCP/Plugins), implement the **Hybrid Logical Clock (HLC) Field-Level Delta Sync Engine** (`POST /api/sync/push`, `GET /api/sync/pull`), add the **"Upgrade Demo to Account"** flow, and configure the **GitHub Actions CI/CD** pipeline.

- **In Scope**: Cloudflare Worker + D1 setup (`wrangler.toml`), Better Auth (Passkeys + Email + API Keys), HLC field-level merge sync endpoints, client background sync worker + offline outbox flusher, Demo-to-Account migration modal, `.github/workflows/ci.yml`.
- **Out of Scope**: Native Swift iOS app (`v1.0`), Cloudflare R2 media uploads (`v1.4` & `v1.5`).

## 3. Step-by-Step Implementation Tasks

### Step 1: Better Auth & Cloudflare D1 Setup (`apps/api` & `packages/db`) (Linear 10.1)
1. Add Better Auth tables (`user`, `session`, `account`, `verification`, `passkey`, `apikey`) to `packages/db/src/auth-schema.ts`.
2. Configure `apps/api/src/auth.ts` with `betterAuth({ database: drizzleAdapter(env.DB, { provider: 'sqlite' }), plugins: [passkey(), apiKey()] })`.
3. Configure `apps/api/wrangler.toml` with the D1 binding (`[[d1_databases]] binding = "DB"`) and static assets serving `../web/dist`.

### Step 2: HLC Field-Level Delta Sync Engine (`packages/shared`, `apps/api`, `apps/web`) (Linear 10.2)
1. In `packages/shared/src/sync-protocol.ts`, implement and unit-test `mergeRecordFields(existingRow, incomingMutation)`:
   - Compares per-field or per-record `hlc` timestamps so if Device A edits `workout.notes` while Device B adds a set or updates `workout.completedAt`, both changes merge cleanly without overwriting each other.
2. In `apps/api/src/routes/sync.ts`:
   - `POST /api/sync/push`: Authenticates user (via Session cookie or Bearer API Token), iterates batched `sync_outbox` records, upserts rows into Cloudflare D1 for that `user_id`, and returns the server's new HLC watermark.
   - `GET /api/sync/pull?since_hlc=...`: Queries all user tables in D1 where `user_id = ? AND hlc > ?` and returns changed/soft-deleted rows.
3. In `apps/web/src/services/sync-engine.ts`:
   - When signed in, automatically triggers `syncNow()` on: (a) local mutation debounce (`1.5s`), (b) `window.addEventListener('online')`, (c) `document.addEventListener('visibilitychange')`.
   - Displays a subtle sync status indicator in the header (`Synced`, `Syncing...`, `Offline — Changes saved locally`).
   - When a user in **Demo Mode** signs up for an account, present `DemoUpgradeModal`:
     - **Start Clean**: Clears demo rows (`DELETE WHERE user_id = 'demo'`) before pulling account data.
     - **Keep My Current Data**: Re-assigns local rows to the new `user.id` and queues them in `sync_outbox` for immediate push to D1.

### Step 3: API Tokens UI & GitHub Actions CI/CD (Linear 10.1 & 10.3)
1. Build `ApiTokensCard` in `Settings` so the user can generate a Personal API Token (`gains_live_...`) to paste into Claude Desktop, ChatGPT, or Gemini.
2. Create `.github/workflows/ci.yml`:
   - Runs `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm format:check`, `pnpm typecheck`, `pnpm test`, and `pnpm build` on every pull request and push to `main`.

## 5. Manual Verification Checklist (User Sign-Off)

1. Run `pnpm dev` (running both Vite and `wrangler dev --local` with local D1 SQLite).
2. Click **"Sign Up / Sign In"**, create an account, and register a **Passkey** (Touch ID / Face ID).
3. Choose whether to **Keep Local Data** or **Start Clean**, and verify the header shows **`Synced`** against local D1.
4. Open a second browser window (or Incognito window), sign in with your Passkey, and verify your routines, workouts, and nutrition logs immediately sync down.
5. Toggle DevTools Network to **Offline** in Window A, log a workout set, then re-enable **Online** and verify the set automatically syncs to Window B within 2 seconds.
6. Go to **Settings $\rightarrow$ API Keys**, generate a Personal API Token, and test calling `GET /api/mcp` or `GET /api/openapi.json` with `Authorization: Bearer <token>`.
