## 3. Step-by-Step Implementation Tasks

### Step 1: Workspace, Oxc, TypeScript & Vitest Setup (Linear 1.1)
1. Create `pnpm-workspace.yaml` including `apps/*` and `packages/*`.
2. Configure root `package.json` scripts:
   - `"dev"`: runs `apps/web` Vite dev server
   - `"build"`: builds packages and apps
   - `"lint"`: `oxlint`
   - `"format"`: `oxfmt` and `"format:check"`: `oxfmt --check`
   - `"typecheck"`: `pnpm -r typecheck`
   - `"test"`: `vitest run`
3. Implement `packages/shared/src/ids.ts` (UUIDv7 generator) and `packages/shared/src/hlc.ts` (Hybrid Logical Clock pack/unpack/send/receive functions) with unit tests in `packages/shared/src/__tests__/hlc.test.ts`.

### Step 2: Shared Drizzle SQLite Schema & Migrations (`packages/db`) (Linear 1.2)
1. Implement all tables specified in [docs/02-database-and-sync-spec.md](file:///Users/shouryan/Programming/gains/docs/02-database-and-sync-spec.md) in `packages/db/src/schema.ts`:
   - `exercises`, `equipmentProfiles`, `routines`, `routineExercises`, `scheduleConfig`, `workouts`, `workoutExercises`, `workoutSets`, `personalRecords`, `bodyMeasurements`, `foodItems`, `savedMeals`, `nutritionDays`, `nutritionEntries`, `tdeeSnapshots`, `aiProposals`, `progressPhotos`, `syncOutbox`, `userSettings`.
2. Export embedded SQL DDL statements so the browser Web Worker can create all tables and indexes idempotently on startup (`runMigrations(sqliteDb)`).
3. Implement `packages/db/src/demo-seed.ts` that populates:
   - 10 core sample exercises (until `v0.2` loads all 5,632)
   - 2 sample routines (`Push A`, `Pull A`)
   - 6 completed sample workouts over the past 2 weeks
   - 14 days of sample body weight logs and nutrition entries

### Step 3: Browser OPFS SQLite Web Worker & Reactive Hook (`apps/web/src/db/`) (Linear 1.3)
1. Install `@sqlite.org/sqlite-wasm` and `drizzle-orm`.
2. Configure Vite `optimizeDeps.exclude: ['@sqlite.org/sqlite-wasm']` in `apps/web/vite.config.ts`.
3. In `sqlite.worker.ts`:
   - Initialize `sqlite3InitModule()`.
   - Install the `opfs-sahpool` VFS (`sqlite3.installOpfsSAHPoolVfs({ name: 'gains-opfs' })`) with graceful fallback to in-memory/IndexedDB if opened in an incognito context where OPFS is restricted.
   - Open `/gains-local.sqlite3` and execute `runMigrations()`.
   - Handle RPC messages (`exec`, `run`, `all`, `get`, `batch`, `seedDemo`, `resetDb`).
4. In `client.ts` & `use-live-query.ts`:
   - Wrap the worker RPC with `drizzle(async (sql, params, method) => ...)`.
   - Whenever an `INSERT`, `UPDATE`, or `DELETE` query runs, emit the affected table names on a local `EventTarget` so `useLiveSQLiteQuery(fn, [tables])` automatically re-fetches in `<2ms`.

### Step 4: Web UI Shell, TanStack Router & Demo Mode Banner (Linear 1.4)
1. Set up Tailwind CSS v4 (`@import "tailwindcss";`) with custom iOS-inspired surface, border, and accent tokens, plus `tabular-nums` utility defaults.
2. Build `AppShell` with:
   - Desktop collapsible left sidebar + Mobile glassmorphic bottom tab bar (`Home`, `Routines`, `Workout`, `Exercises`, `Nutrition`, `Analytics`, `Settings`).
   - Top `DemoBanner` displaying current database status (`OPFS Persistent` vs `Memory Fallback`), row counts, a **"Seed Demo Data"** button, and a **"Reset Demo DB"** button.
3. Build the initial `Home` dashboard route displaying live cards queried from the local SQLite database (Recent Workouts count, Routines count, Latest Scale Weight, Today's Calories/Protein) and the `Settings` page (Theme toggle: Dark/Light/System, Weight Unit toggle: `lb`/`kg`, and Local SQLite Storage Inspector).
